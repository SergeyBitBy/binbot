Ты - senior Python backend developer, software architect и autonomous coding agent.

Твоя задача - спроектировать и полностью реализовать production-ready Telegram-бота для автоматического мониторинга мерчантов и объявлений Binance P2P.

Это должен быть не демонстрационный пример и не урезанный MVP, а полноценный, структурированный, надежный и расширяемый проект, который:

- запускается локально на Windows через Python + venv;
- может постоянно работать на Ubuntu VPS;
- на production запускается и автоматически перезапускается через systemd;
- НЕ использует Docker;
- НЕ требует Docker для разработки, тестирования, запуска или production deployment.

Не ограничивайся объяснениями и фрагментами кода. Необходимо создать полностью работающий repository/project.

==================================================
1. ОСНОВНАЯ ЗАДАЧА
==================================================

Telegram-бот должен автоматически получать объявления Binance P2P по заданным администратором параметрам, находить уникальных мерчантов, извлекать из объявлений и доступной публичной информации о мерчантах контактные данные, сохранять результаты в локальную базу данных и Google Sheets, отслеживать появление новых мерчантов/контактов/объявлений и уведомлять об этом в Telegram.

Основной pipeline:

Binance P2P
    v
Объявления
    v
Мерчанты
    v
Описание / remarks / auto reply / доступные данные
    v
Извлечение контактов
    v
Нормализация
    v
Дедупликация
    v
SQLite/PostgreSQL
    v
Google Sheets
    v
Telegram notifications

Бот должен работать постоянно.

4. PRODUCTION DEPLOYMENT
==================================================

Production environment:

Ubuntu 22.04 / Ubuntu 24.04

Использовать:

Python 3.12+
venv
systemd

Пример структуры:

/opt/binance-p2p-monitor/
    .venv/
    app/
    data/
    logs/
    scripts/
    migrations/
    .env
    run.py
    requirements.txt

Создать готовый systemd service:

deploy/binance-p2p-monitor.service

Он должен:

- запускать приложение из venv;
- запускаться автоматически после reboot;
- автоматически перезапускать приложение при падении;
- использовать WorkingDirectory;
- корректно работать с .env;
- корректно обрабатывать SIGTERM.

Например использовать:

Restart=on-failure
RestartSec=5

или более подходящую конфигурацию.

Также написать инструкцию:

sudo systemctl daemon-reload
sudo systemctl enable binance-p2p-monitor
sudo systemctl start binance-p2p-monitor
sudo systemctl status binance-p2p-monitor

Логи должны быть доступны как через application logs, так и при необходимости через:

journalctl -u binance-p2p-monitor

- body/query parameters;
- pagination;
- limit;
- response schema;
- merchant identifier;
- nickname;
- merchant verification;
- merchant type;
- remarks;
- autoReplyMsg;
- payment methods;
- order statistics;
- completion rate;

- limits;

Если он не возвращает remarks/необходимые merchant data, исследовать web API.

103. SCAN ALGORITHM
==================================================

Пример логики scan:

1. Load MonitoringProfile.
2. Acquire profile lock.
3. Create ScanRun.
4. Для каждой комбинации:
   asset
   fiat
   direction

   запросить Binance pages.

5. Map raw data в internal models.
6. Deduplicate advertisements.
7. Deduplicate merchants.
8. Apply merchant filters.
9. Extract contacts.
10. Transactionally update DB.
11. Determine:
    new merchants
    new contacts
    new ads
    returned merchants.
12. Commit DB.
13. Queue Sheets synchronization.
14. Queue Telegram notifications.
15. Finish ScanRun.
16. Release lock.

Даже если Sheets/Telegram notification failed:

успешно собранные данные не должны потеряться.
